# Audit 02: Money, Invoicing, Payments, Tax, GL

Scope: invoicing, recurring billing, payments, refunds, Stripe (Connect, Terminal, webhooks), ACH returns, chargebacks, collections, deposits, tax, GL, deferred revenue, and rounding wherever money is computed. QuickBooks sync belongs to another audit; this report only notes where money data is handed to it.

Method: I read every file listed in the brief in full. I grepped the API and the front ends for money math. I ran `tsc --noEmit` on `apps/api` (669 lines of errors, 10+ in each money route) and ran the money tests (`vitest`: 19 of 58 selected tests fail). I also checked rounding and date edge cases in Node. No source files were changed.

Severity: **P0** blocks launch (money wrong, data loss, security). **P1** must be fixed before paying customers at scale. **P2** is polish.
Effort: **S** is under 1 day, **M** is 1 to 3 days, **L** is more than 3 days.

---

## TL;DR

The money layer has the right shape: integer cents, a double-entry poster that refuses unbalanced journals, deferred schedules, and an ACH R-code handler. It is not usable for real money yet:

1. **No Stripe webhook endpoint exists.** ACH settlement, ACH returns, disputes and async card results are never received. The idempotency helper they would use (`webhook.ts`) calls a Prisma model that does not exist.
2. **Nothing schedules recurring billing or revenue recognition.** `generateRecurringInvoices` and `recognizeDeferred` are never called outside tests.
3. **Sales tax is always $0 on invoices.** Settings saves `taxRate` (a percent). The tax engine reads a different key, `taxRates[]` (a fraction). POS hard-codes 7%.
4. **The GL puts sales tax into revenue.** There is no sales-tax-payable account. Contract termination writes a one-sided GL entry, so the trial balance does not balance.
5. **Payments are not safe.** There are no idempotency keys, balance checks run outside the transaction, and refunds have no cumulative limit. Card charges go to Stripe before the database row exists.
6. **No staff money screen shows real data.** The web client calls `/api/api/...` (the prefix is applied twice), so every billing page falls back to hard-coded mock data. `PaymentModal` shows "success" even when the API call fails. The customer portal is 100% mock, and "Pay Now" does nothing.
7. **The tenant-lifecycle job would lock a marina out of Helm** when any one of its boaters has a `PAST_DUE` invoice. It is not scheduled today.
